Time Complexity Analysis

Case Complexity Description
Best Case O(n) Pattern found at the beginning of text on first character comparison
Average Case O(n·m) Pattern is found somewhere in the middle after some iterations
Worst Case O(n·m) Pattern not found or found at the end; all comparisons performed

Where:

  • n = Length of the text
  • m = Length of the pattern

Space Complexity:

O(1) - Only requires constant extra space for variables

Algorithm Characteristics:

  • ✓ Simplest string matching algorithm
  • ✓ No preprocessing required
  • ✓ Works well for small patterns and texts
  • ✗ Inefficient for large texts and patterns
  • ✗ Performs many redundant comparisons

Algorithm Implementation

Pseudocode:

function bruteForceMatcher(T, P): n = length(T) m = length(P) for i = 0 to n-m: match = true for j = 0 to m-1: if T[i+j] ≠ P[j]: match = false break if match: return position i return NOT_FOUND

How It Works:

  • 1. Start from the first position in the text
  • 2. Compare each character of the pattern with the text
  • 3. If all characters match, pattern found at current position
  • 4. If any character doesn't match, move to next position in text
  • 5. Repeat until pattern is found or end of text is reached

Advantages:

  • ✓ Easy to understand and implement
  • ✓ No preprocessing required
  • ✓ Works with any alphabet
  • ✓ Suitable for small datasets

Disadvantages:

  • ✗ O(n·m) time complexity in average and worst cases
  • ✗ Inefficient for large texts and patterns
  • ✗ Many redundant character comparisons
  • ✗ Better algorithms exist (KMP, Boyer-Moore, etc.)
